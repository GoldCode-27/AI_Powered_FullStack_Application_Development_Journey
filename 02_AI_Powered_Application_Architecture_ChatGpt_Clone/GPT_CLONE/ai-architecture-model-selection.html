1 The Anatomy of an AI Application

A helpful way to understand an AI application is to imagine a high-end restaurant. Each part of the app maps to a role in the restaurant.

🍽️ Restaurant analogy: The chef (AI model) is locked in the kitchen and only cooks based on the ticket (prompt). The waiter (backend) takes orders, checks permissions, and translates messy human language into precise instructions. The dining room (frontend) is where customers interact and see results.

The “Brain” (LLM API – Inference Layer)

External services like OpenAI API or Anthropic API provide raw intelligence. They act as translators between your code and the underlying neural network. Think of it as the genius chef who knows thousands of recipes but never sees customers directly — only what’s written on the ticket (the prompt).

  • Models like GPT-4, Gemini, and Claude sit behind an API.
  • They don’t know your users directly — they only respond to prompts and data you send.

The Backend (Orchestrator)

The application logic layer, typically built with FastAPI or Node.js/Express. It manages:

  • Prompt Engineering: formatting user input into a structured prompt for the LLM.
  • Authentication & Guardrails: verifying users and filtering malicious inputs.
  • Asynchronous Tasks: managing long-running AI generations to prevent timeouts.

Like a waiter, it receives requests, checks permissions, and translates human language into structured instructions. For example: “I want that spicy thing I had last time” becomes “Dish #42, extra chili, for table 5.”

The Frontend (The Interface)

The user interface where users input prompts and view results. Modern AI apps often handle real-time streaming (via Server-Sent Events) to display the LLM’s response token-by-token, creating a typing effect.

2 Essential Terminology for AI Architectures

Context Window

The number of tokens a foundational model can process in a given prompt. A larger context window lets the model access more information, leading to more coherent and relevant responses.

Scale example – 1 million tokens can process:
  • 50,000 lines of code (80 chars per line)
  • All text messages you’ve sent in the last 5 years
  • 8 average-length English novels
  • Transcripts of over 200 podcast episodes
  • 1 hour of video without audio
  • ~45 minutes of video with audio
  • 9.5 hours of audio

Tokens

The smallest unit of text a model processes — think of it as a piece of a word. In English, a token is roughly three-quarters of a word.

  • Why it matters: Tokens drive costs (billed per token) and define the limits of a model’s memory (context window).
  • Every product decision involving text length or conversation history comes back to tokens.

Parameters / Weights

The internal numbers a model has learned during training. When people say a model has 70 billion parameters, they’re describing its size and roughly its capacity.

  • More parameters → more capable, but slower and more expensive to run.
  • A 7B model can run on a laptop; a 400B+ model needs serious infrastructure.

Inference & Performance

Training happens once. Inference happens every time a user hits your feature — and it’s where your costs live.

  • Inference: running a trained model to get an output. Every user prompt triggers inference.
  • Latency vs Throughput: Latency is how long a single request takes (user-facing). Throughput is how many requests per second (system-level). You often trade one for the other.
Use case matters: A chatbot needs low latency (users hate waiting). A batch document processor needs high throughput (process 10,000 docs overnight).

3 Controlling the Model (The Knobs)

Sampling techniques control how language models choose the next word during text generation. The most common parameters are Temperature, Top-k, and Top-p. They directly affect reliability, creativity, latency, and cost.

First thing to remember: All these parameters influence one core process — how the model chooses the next token. A token is a small piece of text used internally by the model (a word, part of a word, punctuation, or a space).

Temperature – The Creativity Thermostat

Controls how adventurous the model is when picking the next word. It reshapes the probability distribution and typically ranges from 0 to 2.

  • Low temperature: safer, more predictable text.
  • High temperature: more creative and varied text.

Top‑k – Restricting the Candidate Pool

Forces the model to choose its next word from only the k most probable words.

k value Effect Example for “I like to drink…”
Small (e.g., 5) Narrow, focused, safe {water, coffee, tea, juice, milk}
Large (e.g., 50) Wider variety, unexpected twists {smoothies, cocktails, hot chocolate, kombucha…}

Think of it like a menu: small k = limited popular dishes; large k = full menu including rare items.

Top‑p (Nucleus Sampling) – A Dynamic Filter

Selects the smallest group of words whose combined probability adds up to a threshold p. This is more adaptive than Top‑k.

Example
Prompt: “The capital of France is…”
p = 0.9 → almost always “Paris”
p = 0.95 → might consider “Lyon”, “Marseille” if distribution allows

Top‑p adapts naturally: narrow when the answer is obvious, broader when multiple paths are possible. Many people choose either Top‑k or Top‑p, but not both.

Putting It All Together

Task Temperature Top‑p
Coding / Factual Q&A Low (e.g., 0.2) Moderate (e.g., 0.8)
Creative Writing / Brainstorming High (e.g., 0.8) Moderate to high (e.g., 0.95)
General Chat Balanced (e.g., 0.5) Moderate (e.g., 0.9)

4 Model Selection Strategy

Choosing a model is like choosing the engine for your car — balance power, cost, and fuel usage for your specific job. Here are the five main considerations.

Parameter Size

  • Small (7B–8B): fast, inexpensive — good for simple chatbots, categorization, summarization.
  • Larger (70B+): slower, pricier — better at complex reasoning, coding, hard logic.
  • Huge (400B+): like GPT-4-level — best performance but highest cost; use only when truly needed.

Context Window Size

  • Standard (~8K tokens): fine for normal chat and short documents.
  • Larger (100K+ tokens): handle long PDFs, research papers, multiple documents — ideal for RAG systems.
  • Advanced (e.g., Gemini 1M tokens): analyze extremely large codebases or transcripts.

Pick a model whose context window matches your maximum expected prompt size.

Modality

What types of inputs and outputs the model supports:

  • Text-only: takes text, outputs text (e.g., Llama 3).
  • Multimodal: can take images, audio, sometimes video, in addition to text (e.g., GPT-4V, Gemini).

If your app analyzes screenshots, photos, or PDFs with images, you need a vision-enabled model.

Capability Specialization & Pricing

Different models excel at different tasks:

  • Coding: Claude 3.5 Sonnet, GPT-4o.
  • Creative writing: Some models are tuned for storytelling.
  • Speed & low cost: Gemini Flash, GPT-4o-mini — ideal for high-traffic apps.
Pricing strategy: Providers charge per million tokens. A common approach is to use cheaper models (e.g., GPT-4o-mini, Gemini Flash) for 80–90% of everyday tasks, reserving expensive flagship models for rare, high-value queries.

Proprietary vs Open‑Source

Option Examples Pros Cons
A: Proprietary GPT-4o, Gemini Pro, Claude 3.5 Easy integration, highly capable, scales automatically Less control, ongoing API costs
B: Open‑source Llama 3, Mistral, Gemma Full control, privacy, no API costs Need to manage GPUs and servers, more complexity

For this course, Option A (Gemini or OpenAI) is recommended so you can focus on building features rather than maintaining infrastructure.

5 Prompt Engineering Strategies

Prompt engineering techniques are strategies used to design and structure prompts — input queries or instructions — provided to AI models. They guide generative AI systems to produce accurate, relevant, and contextually appropriate responses.

Understanding Prompts

A prompt is the input text or query provided to an AI model to generate a response. The design significantly impacts output quality. There are three primary ways to structure prompts:

Type Description Example
Direct instructions Clear, specific commands for straightforward tasks “Write a poem about nature.”
Open‑ended instructions Less restrictive; encourage exploration and creativity “Tell me about the universe.”
Task‑specific instructions Precise, goal-oriented tasks (translation, calculation) “Translate this text into French: Hello.”

Key Techniques in Prompt Engineering

To demonstrate, we’ll use a central task: “Explain the concept of climate change, its causes, and its effects in a way that is accessible to a general audience.”

Zero‑shot Prompting

Ask the model to perform a task without any prior examples. Relies entirely on pretrained knowledge.

Zero‑shot prompt
Explain the concept of climate change, its causes, and its effects in simple terms.

Few‑shot Prompting

Include a small number of examples within the prompt to demonstrate the task.

Few‑shot prompt
Explain topics in simple terms.
Example 1:
Topic: Photosynthesis
Explanation: Photosynthesis is how plants use sunlight, water, and air to make their own food.
Example 2:
Topic: Gravity
Explanation: Gravity is the force that pulls things toward each other, like keeping us on the ground.
Now explain:
Topic: Climate Change
Explanation:

Chain of Thought (CoT) Prompting

Encourages the model to reason step by step, breaking the problem into smaller components.

CoT prompt
Explain climate change step by step.
Step 1: Define what climate change is.
Step 2: Explain the main causes.
Step 3: Describe the effects on the planet.
Step 4: Give a simple conclusion.
Now follow these steps to explain climate change in simple terms.

System Prompts vs User Prompts

Most LLM interfaces have two types of prompts:

  • System Prompt: sets the overall behavior. Example: “You are a helpful Python tutor who explains concepts using simple analogies and provides code examples.”
  • User Prompt: the specific request. Example: “Explain what a decorator is.”
Pro tip: Use system prompts to set consistent behavior across multiple conversations. For a customer support bot, include tone guidelines, topics to avoid, and error-handling instructions.
Final takeaway: Prompt engineering techniques are essential for optimizing AI interactions. By using structured approaches like zero-shot, few-shot, and chain of thought, you can tackle a wide range of tasks — from chatbots to decision-making and education. Despite challenges like hallucinations, the applications continue to expand.
